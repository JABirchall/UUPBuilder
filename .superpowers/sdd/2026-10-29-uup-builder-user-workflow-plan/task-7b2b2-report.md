## Callback, cancellation and native lifetime

The documented multithreaded callback ABI is DWORD/WPARAM/LPARAM/PVOID. One `syscall.NewCallback` trampoline is allocated once; it routes through one mutex-protected slot by a non-reused integer generation, never a Go pointer. No closure is allocated per run. Slot reservation occurs **before ownership transfer** or source/provider/privilege use, so a refused duplicate cannot receive an owner able to close an active run's native lifetimes. The slot remains held through inspection and Close.

Callbacks admit/increment in-flight delivery under the hub lock, copy only documented bounded values while valid, and synchronize session evidence. PROCESS checks the supplied full destination path against the exact source-derived name set and never suppresses an entry by changing its BOOL. FILEINFO copies a fixed `WIN32_FIND_DATA`, including image hardlink indexes as diagnostic image values, not NTFS IDs. Progress is bounded to 0..100 and never proves return. Unsupported/malformed/unknown/outside paths or messages and native errors/warnings latch incomplete evidence. No native error is skipped.

The callback string ceiling is 4,096 UTF-16 units plus the 4,096-byte decoded path bound. Current-process `ReadProcessMemory` copies use checked exact transferred sizes, 64-byte chunks that do not cross a memory page, and fixed 4-byte PROCESS/fixed-structure FILEINFO reads; no callback integer is converted into a retained Go/native pointer. This also permits inaccessible-pointer negatives to refuse rather than dereference invalid memory. Delivery is capped at 4,194,304; after failure/exhaustion/cancellation further payload copying stops. Ordinary messages retain only counters and the latest copied FILEINFO, plus the first bounded failure, rather than a per-file log. At most one source-derived callback-name map exists. Test Go buffers are pinned during synthetic delivery.

Cancellation requests documented `WIM_MSG_ABORT_IMAGE` at PROCESS/QUERY_ABORT. Other messages retain their documented SUCCESS return, including FILEINFO. The apply call is synchronous; cancellation cannot detach it, close/unload beneath it, or substitute for real return. The installed invocation and no-impersonation checks stay on one locked OS thread; native callback threads remain independent.

After return, operation-time module observations are captured while the provider and native handles are still live. This is a bounded process mapping/hash observation, **not proof of the full transitive operation closure**. The exact non-null WIM registration is unregistered using its exact callback function pointer, not its registration index or NULL/global unregistration.
