## Contracts and identity

`BindSourceExpectations(ctx, *PreservationProof, ComparisonLimits)` accepts the live sealed B1 proof. `BoundRecipe` now retains the exact original verified Oracle supplied to `BindCanonical`; its claim must continue matching the original immutable descriptor. This was the controller-approved narrow source API extension. The recipe still borrows the original MetadataArtifact and ReferenceView, including both content parents. It transfers no Close ownership. Original source/index/metadata/Oracle/reference/resource/provenance identities remain those of the original producers. The generated WIM is a bound prerequisite, never the comparison oracle.

`Oracle.RecordCounts` scans immutable lengths/counts without Snapshot or JSON. `EntryAt`, `SecurityAt` and `GapAt` precharge nested record/string/slice storage before copying; zero is an exhausted allowance. Recipe accessors bracket copies with parent checks. The new expectation boundary uses those accessors to retain every original dentry, UTF-16 name/short name/path, stream role/hash/length/reference, attributes/three raw source FILETIMEs, complete raw security descriptor and parsed SID/ACL/ACE identities, hardlink group, reparse union and tagged data. It retains the original Oracle claim and every original gap unchanged. Original framing/unreferenced bytes remain accessible only through B1's fixed original metadata resource reader, with their original gaps/offsets; no new complete-Snapshot clone is hidden behind counts.

The source boundary rereads and checks the entire original metadata SHA1/SHA256 before and after expectation construction. Comparison repeats those source rereads before/after its observations. Exact declared read cost is charged before I/O. Reparse blobs are read through the exact original stream ordinal/reference, capped at native framing size and checked against original SHA256. Other default/named bytes use the original verified resource SHA1/size/SHA256 lineage. `SourceExpectations.ReadOriginalAt` accepts only an original entry/stream ordinal, checks its original resource identity and both proof lifetimes, caps a read at 64 KiB, and accepts no arbitrary path/hash/reader. B5's retained content handles retain their existing custody guarantees.

`SourceExpectations.EntryAt`, `SecurityAt`, `OriginalGapAt` return independently copied values under explicit allowances and check source/output revocation. The descriptor is historical scalar data. Zero, foreign, closed and caller-mutated public descriptors cannot create authority. Tests close original producers, generated output and native scopes separately; exports/readers then refuse. No serialized constructor was introduced.

## Native observation boundary

The controller approved `OwnedTree.ObserveInventory` because enumerating expected paths or copying the fixture ledger would not be independent inventory evidence. It enumerates actual names from held directories using the existing bounded, non-following native primitives, then compares names against ledger identities. It retains actual and ledger IDs separately, native failure codes where available, and known/unknown/missing/changed/reparse/denied/failed/duplicate status. Unknown entries are never opened, read, adopted or traversed. Only exact known held directories may be traversed. Errors, drift, cancellation and exhausted residuals leave `Complete=false`. Owner/root/parent checks remain active; successful file-containing cleanup remains unimplemented.

`OwnedTree.ReadOwnedAt` reads only an existing held created ordinary file or an exact recorded named-stream handle. A small parallel name ledger binds recorded stream names to the already-retained handles; it grants no descendant admission. It caps names and 64 KiB reads, refuses colon-path/unrecorded-stream/arbitrary-entry reads, and checks owner/native identity and observed object facts before/after I/O. `CheckObservationLive` rechecks the owner/root lifetime. No cleanup or generic jobstore guard was weakened.

`ComparePreservation` publicly accepts only `*SourceExpectations` and the existing `*OwnedTree`, requires its exact proof digest/nonzero root/operation identity, independently inventories actual names, inspects each known matching object, hashes every supported default/named stream and rechecks every observed entry plus the entire actual inventory. Native ID equivalence and source-derived file link counts are checked separately from content hashes. Missing/extra paths, unknown names, outside links, replacements, denied/incomplete fields and drift prevent complete component comparison. Both actual inventories are retained. Exact source/observed mismatch witnesses include field/path, complete stream names, original/native security bytes, native hardlink IDs and packed EA name/flag/value bytes. Partial reads are unresolved and are not counted as completely compared streams.

`PreservationComparison.Evidence(ctx, allowance)` deep-copies retained mutable witness slices only after charging; `Serialize(ctx, allowance)` reserves a conservative JSON escaping/base64/numeric/encoder-scratch bound before encoding, then checks context and both live parents again. JSON is historical component evidence and has no admission capability. Accessors/exports recheck open/identity lifetimes; they do not repeat the complete prior byte/native observations.

Native enumeration, metadata queries, content reads and final rechecks **are not an atomic filesystem snapshot**. An identity can remain held while a namespace/ADS changes between observations or after the final recheck. Same results at both boundaries do not establish whole-interval stability or ADS atomicity. Single synchronous OS calls and JSON encoding cannot be preempted; context is checked between/after them before publication. No current whole-image or future production-preservation authority follows from `Complete`.

## Exact supported and unknown rules

- Paths and names compare exactly, retaining original UTF-16. No case folding, guessed filenames or replacement-character normalization grants a match. Unsupported native paths and nonempty short names remain explicit requirements; B1 has no short-name observation here.
- Ordinary default/named stream roles compare exact observed names, sizes and full SHA1/SHA256. Empty encoded source data uses the empty-byte SHA256 and size zero, without inventing a resource. Directory placeholders and unused main hashes are not data streams; an observed zero-size directory default stream is permitted. Additional native data streams refuse. EFS/unsupported source roles remain unresolved.
- File hardlink groups use original nonzero IDs and exact name counts; ID zero denotes a distinct source file. Native volume/128-bit IDs establish equivalence; equal bytes never do. Native link counts must equal source group counts, excluding outside links. Directory file-link counts have no corresponding stored source value; directory identity/topology is checked through the held ledger/actual walk, not an invented source count.
- Attributes and creation/access/write FILETIMEs compare exactly. WIM dentry framing stores no change time: native change time is retained/rechecked but has no invented source expectation.
- Security comparison requires complete owner/group/DACL and SACL queries. If either is denied/incomplete, native field requirements block complete security comparison; available raw B1 observations remain historical evidence. Complete queries compare owner/group SID bytes, control, null versus absent ACLs, ACL revision and ordered **entire raw ACE bodies**, including callback application data, GUIDs and opaque flags. The SACL-specific control mask is `0x2a30`; non-SACL control comes from the owner/group/DACL query. Shared self-relative/RM control and RM header byte are checked in both queried headers. Callback/opaque bytes can be compared for preservation without evaluating authorization conditions; the original Oracle's `ace-semantics` gap stays unchanged.
- Self-relative component offsets/order and zero descriptor layout/ACL unused-space padding do not identify a semantic change. Original raw descriptors survive. Nonzero unexplained bytes, unknown control/header semantics and malformed framing remain unresolved; ACE order/body differences are never normalized away. Empty original security records remain unresolved rather than panicking or inheriting invented security.
- Source tag 2 is decoded as packed `(uint16 value length, byte name length, byte flags, NUL-terminated name, value)` records without per-record padding. EA name, flag and value bytes compare exactly, independently of native FILE_FULL_EA_INFORMATION layout. Only flags 0/0x80 have the pinned framing contract. Duplicate/malformed names/tags, unknown flags and every other source tag remain explicit requirements. Absence of tag 2 means no recorded EAs; unsupported tags cannot be treated as evidence of absence.
- Reparse tag/reserved header and exact source blob bytes compare without following targets. Third-party GUID data remains part of the original blob. No destination relocation is accepted/inferred. An unexplained relocation is a mismatch. Microsoft GUID-form native buffers without a source-exact reconstruction rule are explicitly unresolved. Unknown WIM reparse flags/reserved fields retain their original gaps.
- Original gaps other than raw ACE preservation and successfully interpreted tag-2 framing remain unresolved requirements. The result cannot silently turn original Oracle completeness true. The complete synthetic fixture intentionally has original Oracle completeness false for callback semantics while the separate raw-preservation comparison can complete.

## Bounds

Public zero limits select ceilings: 262144 entries, 65536 original security records, 524288 encoded source streams/native stream records per observation pass, 262144 requirements/mismatches, 1 MiB path/name/variable witness fields, 64 GiB aggregate reads, 512 MiB accounted result and 512 MiB serialization allowance. Source scalar shape/string checks precede nested copies. Record/EA/map/result/read/serialization costs are charged before their variable allocations/copies/I/O. EA decoding additionally caps 65536 packed records per tag and 1 MiB input; residual zero never selects a default.

The public native adapter retains B1's lower ceilings: 4096 created entries, depth 32, 16 MiB inventory reads, 4 MiB inventory result, 64 KiB metadata buffers, 256 streams/EAs per object, plus the caller's lowered remaining allowances. Unknown inventory cannot bypass these through source counts. Source rows are complete; a source beyond the existing fixture-native scope returns bounded incomplete/refusal rather than an unbounded adoption route. Accounted storage includes scratch/reserved record overhead and retained result copies; it is not a whole-process Go/native peak-memory guarantee. Existing producer memory, OS-managed GetSecurityInfo allocation and runtime/allocator retention remain outside that claim.
