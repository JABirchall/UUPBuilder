## Implemented contracts

`engine.BindPreservationProof` accepts only the same live `source.BoundRecipe` retained by the production `Reconstruct` output. It freshly verifies that held output's SHA256/custody and checks recipe/proof identities before producing a private immutable proof. Zero, foreign, closed and receipt-only objects refuse. Its copied descriptor binds the source/target, frozen manifest, original index/metadata/oracle/reference identities, original resource identities and provenance, recipe/proof digests, exact generated WIM SHA256/size, baseline image 1, fixed future actions and conservative privilege/provider requirements. Caller mutation cannot change the authority. The original metadata reader comes from the original verified producer, not the generated WIM; it checks both borrowed lifetimes and caps each read at 64 KiB. Original sampled PathFacts and full raw metadata/resource identities remain independent expectations. They do not assert complete metadata interpretation or comparison.

`platform.ObserveImagePreservationPrivileges` opens only TOKEN_QUERY. It refuses thread impersonation, records presence/raw attributes for the three fixed named LUIDs and checks the retained process-token identity. The conservative `image-restore-full-security-inspection-v1` profile covers SeBackupPrivilege, SeRestorePrivilege and SeSecurityPrivilege for backup reads, owner/DACL restoration and SACL inspection. The controller explicitly approved this conservative profile **without claiming WIMApplyImage-specific sufficiency**: Microsoft's WIMApplyImage contract does not state a complete privilege list. `GuardImagePreservationPrivileges` accepts already-enabled requirements only. There is no real adjustment adapter or TOKEN_ADJUST_PRIVILEGES open. Private synthetic native-call ports exercise enable, checked PreviousState, partial assignment, rollback, query-after-restore and latched restore/close errors. Malformed returned previous names/LUIDs cannot become restoration authority.

The controller approved the focused `jobstore.Transaction.ClaimDirectory` / `DirectoryClaim.Release` hook rather than labeling a directory as a mount or making an independent journal. It reuses the active transaction/single writer and requires the exact proof digest in an existing `preservation-proof` intent input. The original intent's job/stage, input/tool/rule/config/plan identities and predecessors are bound by an intent digest. A generated fresh path is journaled before creation; native root identity is journaled before success. Partial creation returns its retained claim/scope and an error. It cannot adopt an existing path or reopen persisted tree claims. A low-level Begin and this hook still do not authorize the worker graph or a native operation.

`platform.OwnedTree` borrows the exact private local NTFS workspace and retains parent/root/created-entry handles and native volume/file IDs. It rechecks the owner marker's identity/content. Parent traversal opens one validated component at a time with FILE_OPEN_REPARSE_POINT and rejects reparse ancestors; descendants are never inferred owned merely because they lie under the root. Its ledger records actual created ordinary files/directories, explicit hardlink names and validated named streams. Identical bytes do not establish a hardlink group. Limits bound entries (4096), depth (32), logical bytes (64 MiB), traversal reads (16 MiB), accounted result/ledger storage (4 MiB), path lengths and stream counts. Positive options only lower ceilings; exhausted remainders never select defaults.

Directories retain no-delete-sharing pins **without DELETE access**. Holding DELETE on the destination directory conflicted with native FileLinkInformation's internal sharing on this host. Cleanup first proves the complete bounded namespace, file identities, internal hardlink counts and named-stream ownership; unknown entries/ADS, outside links, reparses, replacements, changed ownership and exceeded budgets preserve/refuse before deletion. It deletes exact held file objects, never recursively deleting an arbitrary path. For directories it closes the no-rename pin only after proof, opens a single leaf relative to a retained parent, rechecks the original native ID and then marks that exact object for deletion. A missing or replaced final root refuses. Cancellation/partial close/removal errors are retained; Close releases handles and explicitly reports unresolved preservation rather than claiming deletion.

An unresolved directory claim always makes generic jobstore resource inspection preserve/refuse. The generic regular-file, one-link, no-reparse checkpoint/topology guards and their limits remain strict. Release requires an empty same-identity scope and complete independent nonoverlapping OS mount inventory plus bounded generic workspace topology. A released path is no longer known/owned; if it reappears it is explicitly foreign/preserved. Store.Close latches unresolved claim/handle errors, including when an empty tree was manually removed but its durable claim was never released. No mount/unmount or recovery/replay feature was added.

`OwnedTree.Observe` accepts a held created entry or its root, not arbitrary paths. It records raw FILE_BASIC_INFO attributes and creation/access/write/change FILETIMEs, FILE_ID_INFO volume/128-bit ID, native link count, self-relative owner/group/DACL security bytes, separately privileged SACL bytes, counted raw named stream records, full EA name/value/flag bytes and reparse tag/data. The native buffers and parsed lengths/counts/offsets have explicit read/result ceilings. Unsupported, access-denied, missing-privilege, malformed and incomplete observations stay explicit; aggregate Complete requires every required field. It does not follow targets, interpret opaque ACE/EA semantics or compare output against itself. GetSecurityInfo's OS-managed LocalAlloc allocation is outside the Go result budget; its returned length is checked before a Go copy and LocalFree failures are retained. This is a bounded observation, not an atomic metadata snapshot or image-preservation proof.

`NewNativeApplicationRequest` fixes the same proof/WIM, exact transaction-intent digest, baseline image and native owned destination identity. A second generated WIM from the same original recipe cannot borrow another output's destination binding. There is no execution method. Its specification lists explicit missing authorization/provider/privilege/descendant-custody/comparison/native-completion/cleanup and production-composition prerequisites. `ApplicationResponse` defines the later evidence shape (bindings, provider, privileges, native completion/cancellation, inspection/comparison failures and preserved resources); descriptive caller data grants no authority.

The controller approved the subsequent mechanical responsibility split after GREEN: owner state/lifecycle, native relative primitives, creation/link/stream records and topology/checked cleanup now occupy four focused Windows files (263/125/223/344 lines at the split). No broad abstraction, worker protocol, graph, Toolchain or unrelated restructuring was introduced.
