## APIs and authority

`DirectoryClaim.CheckLive(ctx)` checks the retained open writer handle, active owning transaction, unreleased/nonzero claim, matching source-proof input and intent digest, exact saved stage intent/scratch/uncommitted state, one matching directory journal record, workspace/operation/path/native root identity and the original live tree. Closed, released, foreign, missing/partial, changed-stage and inactive-writer cases refuse. It checks the retained state originally written by the single writer; it does not import/reopen a persisted claim, release anything or authorize descendants/native mutation. Existing public claim and release signatures and generic guards are unchanged.

The separate platform APIs are `NativeObservationProfile`, `PreflightNativeObservation`, `BorrowNativeObservation` and `NativeObservationSession.{Identity,CheckObservationLive,ObserveInventory,Observe,ReadOwnedAt,BeginMetadataPass,Evidence,Close}`. `NativeObservationPath`/`NativeObservationStream` are bounded inspection descriptors, **not** proof of an imaging attempt or creation. The platform session borrows the original root/parents and owns only its acquired read handles. It never writes `OwnedTree.entries` or calls cleanup/release.

The only production comparison integration is the **private** engine `newSourceNativeObservation`/`sourceNativeObservation` wrapper. It derives its descriptors from the exact live sealed `SourceExpectations`, checks the live proof/output and exact claim/proof/root binding, and brackets observation/content calls and metadata-pass resets with those lifetimes. Public `ComparePreservation` still accepts only B1's `OwnedTree` and its original ceilings. The private kernel recognizes only this concrete wrapper for the separately approved larger inventory profile; no generic caller-native-port constructor is exposed. Caller descriptors, JSON, paths or comparison booleans cannot mint `ObservedSourceContractResult`, Toolchain, NormalizedSource, assembled success, B1-created ownership or deletion rights. That future result capability is deliberately absent here.

## Observation and handle lifetime

Actual names come from directory enumeration, independently of the expected table. Only exact expected names/types are opened, one leaf at a time through retained parents with `FILE_OPEN_REPARSE_POINT`; normal observation handles request read/metadata rights and deny write/delete sharing. The session retains the actual native IDs separately from the enumerated IDs and from the source descriptors. `InventoryEntry.RetainedIdentity` is observational; `LedgerIdentity` is not populated by this session. Unknown directories are recorded but never opened/traversed. A known directory that is unexpectedly a reparse is refused; a source-expected reparse object is inspected without following its target. Unsafe/reparse source ancestry, duplicate/case-colliding names, malformed paths and unsupported stream descriptors refuse before observation.

Content reads accept only a bound expected path and exact recorded stream name, at most 64 KiB, capped to the original declared extent. No caller colon path/arbitrary stream/hash/reader is admitted. Exact parent/name/held ID checks and native facts bracket reads. ADS handles are retained immediately, checked against the original file ID and closed with all other acquired handles. Missing/replaced/type-changed/denied/drifting names or incomplete native fields prevent complete comparison; failed native field results remain in the returned metadata. Known inventory failures retain the available enumerated/held identity, native code and bounded cause. This addresses the new observer's owning M1 provenance requirement without modifying B2A's deferred legacy branch.

Temporary opens count too: root/owner validation can hold two temporary handles simultaneously, metadata can hold a SACL inspection handle, and name rechecks temporarily reopen one component. Acquired entries and streams close in reverse acquisition order; borrowed root/parent handles stay with their original owner. `Close` always reports the exact preserved scope/root identity and unresolved durable claim. It latches close failures and is idempotent. A fixed emergency slot retains the first known identity/native cause if failure evidence itself exhausts its budget; subsequent unavailable evidence is explicitly marked exhausted. All acquired handles are still closed. `Evidence` is copied historical data (including after Close); live comparison exports continue checking their source and native parents.

These calls are **not an atomic snapshot**. Pins on observed streams do not establish a complete ADS namespace or creator provenance. An expected-looking object inserted by another admitted actor before its first observation cannot be authenticated as WIMGAPI-created here. Independent equality never becomes deletion authority. B1 still preserves every file-containing cleanup. The possible directory-ADS-after-proof race remains an explicitly **untested pre-existing inference**. No ACL, oplock, volume, mount, tracing or transaction machinery was added as a workaround.

## Bounds and exact accounting semantics

The new read-only profile has lowerable ceilings: 262,144 entries, depth 32, 524,288 stream records per metadata pass, 262,144 retained/temporary/borrowed-root-parent handle slots, 64 GiB cumulative charged content/query work, 512 MiB accounted session/result/scratch and 512 MiB explicit export allowance. Per-object native buffers remain at most 64 KiB and stream/EA counts at most 256. Paths are bounded to 4,096 bytes with 255 UTF-16 code units per component; stream names are bounded and validated independently. Count/string/record/handle/result/scratch/read/export checks precede their bounded use; exhausted internal residuals never select defaults. No B1 creation/cleanup or jobstore ceiling changed.

`NativeObservationBudget` separates exact source `ContentBytes` per name (including hardlink aliases/ADS), `MetadataCapacityBytes`, nominal `DirectoryCapacityBytes`, `IdentityQueryBytes` and `ValidationAllowanceBytes`. For the planned two metadata passes, variable capacity is **four** per-object buffer/copy allowances (security, SACL, streams, EA), plus fixed basic/ID/native-info work and 16 KiB only for expected reparses. Directory preflight assigns two 64 KiB queries per directory per pass. Additional actual pages still spend the runtime budget and can refuse with partial evidence. Identity work accounts component depth and the declared 64 KiB content-read chunks. Validation reserves bounded owner/root work separately; binding the actual root adds its exact retained-parent-count allowance.

Runtime `ReadBytes = ContentReadBytes + QueryCapacityBytes + ValidationAllowanceBytes`. These are requested/precharged capacities and validation allowances, **not actual disk or returned native query bytes**. `ActualQueryReadBytesKnown=false`: directory/stream queries do not provide a returned byte count. OS-managed `GetSecurityInfo` allocation and caller/producer/runtime/kernel heaps are outside a whole-process memory guarantee. Borrowed producer/claim checks retain their existing independent counters/lifetimes. The preflight is a declared plan plus nominal directory allowance, not a guarantee that unknown native growth or repeated future calls will fit. It is required again with fresh actual source facts before B2B2 may propose execution.

Session metadata/inventory results transfer to the caller's bounded per-call allowance; the session does not retain successful raw metadata. Its scratch reservations are released on return, while internal descriptors, handles and failures remain charged. The comparison kernel likewise releases metadata/security/EA/stream scratch after each observation. It retains conservative actual maps, inventories, requirements, witnesses and a compact SHA256 fingerprint for every initial complete typed observation. The streaming fingerprint includes all fields/statuses/native causes/raw bytes, nested records and nil/empty distinctions formerly compared by `reflect.DeepEqual`. Initial Basic raw witnesses and every mismatch raw witness remain retained. Final field rechecks and both full inventories still run; fingerprints do not assert atomicity. `PeakScratchBytes` distinguishes the reusable high-water allowance from retained `AccountedBytes`.

- [File streams](https://learn.microsoft.com/en-us/windows/win32/fileio/file-streams): stream names and per-stream sharing; no complete namespace snapshot follows from these pins. Existing B1 security/EA/reparse query/parsers are reused, not reimplemented.
